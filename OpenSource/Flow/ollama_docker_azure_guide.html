Step 1 — Install Ollama on your machine
What is Ollama?

Ollama is a runtime that downloads and serves open-source LLMs (Llama 3, Mistral, Gemma, etc.) on your own machine via a simple REST API on port 11434. Your Streamlit app calls http://localhost:11434/api/chat — no API key, no cloud cost.

Pick your OS

macOS / Linux
# Install
brew install ollama
# or via curl
curl -fsSL https://ollama.com/install.sh | sh

# Start the server
ollama serve
Windows
Download the installer from ollama.com/download and run it. Ollama starts automatically as a system tray app.
# Then in PowerShell
ollama pull llama3.2
ollama serve

Models are stored in ~/.ollama/models. Once pulled, they work fully offline.

Step 2 — Run everything locally with Docker Compose
# 1. Copy environment config
cp .env.example .env

# 2. Set your model in .env
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=llama3.2

# 3. Start all containers (Ollama + app)
docker compose up --build

# First run: downloads model (~2 GB), takes a few minutes
# Subsequent runs: uses cached ollama_models volume, instant start
Why two Ollama containers?

ollama is the long-running server. ollama-pull is a one-shot helper that waits 5 seconds, runs ollama pull llama3.2, then exits. This ensures the model is downloaded before the app starts sending requests.

# Verify all three containers are running
docker compose ps

# Stream logs from the Ollama container
docker compose logs -f ollama

# Open the app
open http://localhost:8501

Create a Resource Group and ACR
# Create resource group
az group create --name ai-voice-agent-rg --location eastus

# Create Container Registry (Basic SKU = cheapest)
az acr create --resource-group ai-voice-agent-rg --name aivoiceagentacr --sku Basic --admin-enabled true
3
Build and push your Streamlit app image
# Option A: Build in Azure (no Docker needed locally)
az acr build --registry aivoiceagentacr --image ai-voice-agent:latest .

# Option B: Build locally then push
docker build -t aivoiceagentacr.azurecr.io/ai-voice-agent:latest .
az acr login --name aivoiceagentacr
docker push aivoiceagentacr.azurecr.io/ai-voice-agent:latest
Use Option A if possible

az acr build uploads your source code to Azure and builds in the cloud — faster, no local Docker needed, and automatically pushes to ACR.

4
Verify the image is in ACR
az acr repository list --name aivoiceagentacr --output table

az acr repository show-tags --name aivoiceagentacr --repository ai-voice-agent
Ollama image comes from Docker Hub directly

You do NOT push the Ollama image to ACR. Azure Container Apps pulls ollama/ollama:latest from Docker Hub automatically when the sidecar container starts. Only your Streamlit app image needs to be in ACR.

Step 4 — Deploy to Azure Container Apps
Sidecar pattern — why it matters

Both containers run in the same Container App revision. They share a network namespace, so the Streamlit app reaches Ollama at http://localhost:11434 — zero latency, no public exposure of the Ollama port. They also share an EmptyDir volume so Ollama can cache model weights.

# One-command deploy using the Bicep template
az deployment group create \
  --resource-group ai-voice-agent-rg \
  --template-file azure/main.bicep \
  --parameters containerImage=aivoiceagentacr.azurecr.io/ai-voice-agent:latest \
  --parameters ollamaModel=llama3.2 \
  --parameters sendgridApiKey=SG.xxxxx \
  --parameters productEmail=product@yourco.com \
  --parameters paymentEmail=payments@yourco.com

Or use the one-shot deploy script

# Interactive — prompts for all secrets securely
bash azure/deploy.sh

Key environment variables set by Bicep

VariableValue in Azure
OLLAMA_BASE_URLhttp://localhost:11434 (sidecar shares localhost)
OLLAMA_MODELllama3.2 (or whichever you set)
OLLAMA_TIMEOUT180 (generous, first request cold-starts the model)
DB_TYPEsqlite (uses EmptyDir; swap to mysql for persistence)
APP_ENVproduction
SENDGRID_API_KEYPulled from Key Vault secret reference
First startup is slow (~3–5 min)

When the container app starts for the first time, Ollama pulls the model weights inside the container (~2 GB for llama3.2). Subsequent restarts reuse the EmptyDir cache. For production, mount an Azure File Share as the volume instead of EmptyDir so weights survive restarts.

Common issues and fixes

Ollama shows offline / timeout errors

The sidecar is still pulling the model. Wait 3–5 minutes and retry. Check logs: az containerapp logs show ... | grep ollama. If it keeps failing, increase OLLAMA_TIMEOUT to 300 in the Container App environment variables.

JSON parse errors / garbled AI responses

Small models (phi3, llama3.2) occasionally respond outside the JSON format. The app's fallback returns the raw text as the answer. Switch to mistral or llama3.1 for more reliable JSON adherence. Change OLLAMA_MODEL in Container App env vars and restart.

Persist model weights across restarts

Replace the EmptyDir volume with an Azure File Share mounted at /root/.ollama. This way the model is downloaded once and survives pod restarts and scaling events.

# Restart the container app (forces fresh pull)
az containerapp revision restart --name ai-voice-agent-app --resource-group ai-voice-agent-rg

# Update OLLAMA_MODEL to switch models without redeploying
az containerapp update --name ai-voice-agent-app --resource-group ai-voice-agent-rg \
  --set-env-vars OLLAMA_MODEL=mistral
